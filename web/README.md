# 字谜离合动画工坊 · 网页版（web/）

在 `zigen-app` 拆字数据的基础上实现的 **「选字素 → 标角色 → 出 APNG」** 轻量动画工具网页版。
纯 HTML/CSS/JS，无框架、无构建、无 CDN 依赖，**双击 `index.html` 即可使用**（也可用任意静态服务器托管）。

## 上手（不用读文档，跟着编号走）

三步：**① 输入谜面与谜底 → ② 点字拆解合成 → ③ 配对与生成动画**。页面自己会把流程讲清楚：

1. **谜底和谜面一起填（①）**：谜面必填、谜底可留空。**先填上谜底更好** —— 每次合并出的字
   会直接落到它对应的谜底位上，不必等到最后再来配对；留空只是「最后再填」，流程一样能走完。
   这个工具**不做解谜**，谜底始终是你已知的输入。
2. **步骤轨**（左列顶部）：三个节点常驻显示状态（进行中＝空心粗描边 / 已完成＝实心黑 /
   待解锁＝灰）。点任意节点即可跳到那一步。
3. **谜面工作台（②）—— 上面点字、下面一个零件池**：
   - 顶部字块：**每个字块都挂身份徽标**（字素＝绿 / 衬字＝橙），点一下就是"选中这个字"，
     下方字卡里改它的身份；
   - **字素池**：所有「字素」拆出的部件集中摊在下面一个池子里，**一行一个来源字**
     （行左标出来源字，行内是「整字 + 各拆解部件」，同一字的多种拆法**一次全列出、不区分拆法**）。
     所有零件属于同一个选择集，因此**可以随手拿 A 字的零件和 B 字的零件拼**，
     不必来回切换字卡 —— 「千古」里的 丿(千)+十(古) 就是这样点出来的。
   - **拆解部件与整字**：点一下零件就丢进下面的"待合并"，选中只改 class 不重建 DOM（长谜面也不掉帧）。

   **分类是可选的**：载入谜面时所有字默认就是「字素」，不标注也能从头做到尾（这正是
   "绝大多数纯拆字谜面"的情况）。想把某些字标成「衬字」时再点开那个字改 —— 它们只为谜面行
   配色和讲解服务，不参与拆合（改成衬字后它的零件会从池子里撤走，用到它的合并会级联清掉）。
4. **待合并托盘紧跟字素池**：挑中的零件累积在池子正下方的托盘里，凑齐后点「合并」。
   选 1 个＝直接取用，2 个以上＝拼成一个新字。
5. **步骤门控**：前置条件没满足时卡片收成一行说明；点未解锁的步骤会给原因，不会静默失败。
6. **常驻引导条**（左列底部，sticky）：滚动时始终可见，显示刚刚发生了什么，并在需要时
   给出一个动作按钮 —— 这是回答"下一步做什么"的唯一地方。步骤之间跳转只走顶部的步骤轨，
   卡片里不再重复放「接下来」按钮。
7. **画布空态**：还没生成动画时画布显示「动画会出现在这里」＋一个直接跑示例的按钮。
8. **使用说明面板**：页头「使用说明」打开三步说明，可 Esc / 点遮罩关闭，不阻塞操作。

内置一个示例 `十八口` → 杏（十+八=木，木+口=杏，最短上手路径）。
示例入口只有三个同类按钮：**页头右上角**、**画布空态**、**「使用说明」面板**，
点一下就自动走完「载入谜面 → 两次合并 → 落位成谜底 → 生成动画」，直接可播可导出。
第 ① 步卡片里不再堆示例 —— 示例是给人看效果的，不是填表的一部分。

设计取舍与验收口径见 [`docs/onboarding-spec.md`](docs/onboarding-spec.md)。

## 功能

1. **输入谜面与谜底**：如「十八口」→「杏」。谜面必填、谜底可留空；载入后逐字显示为可点击字块。
2. **定身份**：点字 → 在字卡里选身份（**字素**＝参与拆合 / **衬字**＝不参与拆合），颜色与身份绑定、无需输入颜色；字块上的徽标两类都挂（绿＝字素、橙＝衬字）。
3. **拆解与合并（选定式，无拖拽，支持从多个字提取）**：
   - **字素池**把全部字素的「整字 + 拆解部件」摊在同一处、一行一个来源字，因此**跨字混选不需要切换任何东西**；
     **不区分拆法** —— 一个字在拆字库里有几种拆法，就把几种拆法的部件**一次全摊在这一行**（跨拆法同字形只留一块；如「木」= 十 人 八 一 小），
     不用先选拆法再挑部件；手写的那条排在最前，拆字库多出来的部件也一并摊出；池子首行是「**已拼出**」——合成结果本身也能继续当输入，所以「十+八=木 → 木+口=杏」这样的连环照样点得出来（被后一次合并吃掉的中间产物标「已用」）；
   - **每个字都能加部件**：拆字库没收录（如「龘」这类）或拆得跟你想要的不一样时，直接在那一行的末尾写 ——
     不用先点「自定义拆法」，输入框一直都在。写「木口」或「木 口」回车 → 立刻成为这个字的部件、输入框留着可以**连着加**；
     不想打字就点「**选部件**」，从「本谜面已有的部件 + 常用字根」里点一下加一块（面板不收起，可以连着点）。
     手写加进来的部件是**虚线块、带 ✕**（点 ✕ 撤销这一块；拆字库摊出来的部件没有 ✕，那不是你加的），排在整行最前面。
     **不去重**（所以 林 = 木 + 木 写得出来），最多 8 个；有手写时给「用回拆字库」一键还原；
     改拆法会级联清掉用到这个字的合并（否则部件字形换了、合并记录还留着旧字形）；
   - 点选 **1~6 个**可合成对象（整字 / 部件 / 合成结果，可跨多个字提取，如 人+人+人=众、木+木+木=森；**单选=直接提取该字素**成字，如「估」中取「古」）→ 合并；
   - 自动给出候选合成字（恰好由所选部件合成的优先），也可手填；
   - **笔画层等价匹配**：字面部件匹配不到时，把所选部件展开到底层笔画再匹配（如 亻+一 → 千：亻=丿丨 与 千 的 丿十=丿(一丨) 笔画多重集一致）；
   - **单次使用约束（软锁定）**：每个部件实例、整字、合成结果只能用一次——整字被用则其全部部件一并锁定；某字「任一部件实例」被用则整字锁定（整字会重新引入已消耗材料），但该字其余未用部件仍可独立参与后续合并（如 丿(千)+十(古)=千 后，十(千)、口(古) 仍可合成 古）。被消耗对象标「已用」不可再选；删除合并（含级联）后自动解锁。动画中只拆出实际被使用的部件。
4. **谜底配对（多段谜底）与动画编排**：
   - 谜底常由多段各自合成（如 木+口=杏、艹+化=花 → 谜底「杏花」）；
   - 第三步提供**配对看板**（不是一段说明文字）：**一行 = 一次对应** ——
     `[杏 · 木 + 口] ──▶ [谜底第 1 字 杏]`，左边是"这一笔拼出来的字（附上它由什么拼成）"，
     箭头指向它落户的谜底位；**实线 = 已配对，虚线 = 还没有合成结果承担它**。
     点左侧方块「拿起」，再点任一谜底位即可连上；拿起点另一个结果所在行 = 两个位置**互换**；
     每行带「✕」解除（解除只否决这一个结果，字形对得上的另一个仍会自动顶上）。
     没连上的结果收在下方列表里；未手动改过时按字形自动配对（同字优先、余者按序填槽）。
     三条硬规则：① **中间产物不能承担谜底** —— 被后一次合并吃掉的合成结果（`木` 被 `杏` 吃掉）不出现在配对面板里，否则末帧会出现"答案字凭空消失"（旧实现把 `十八口 → 杏子` 自动配成 木→子，末帧只剩杏）；② 手动配过之后，**空槽仍会用字形对得上的结果自动补位**，因此不会出现"同一个字先以合成结果的身份出现、末尾又被弹出一个"的重复段；③ 手动**解除**过的结果不参与补位（那是明确的"别放这里"），该槽位改为末尾直接弹出，面板写明「无合成 · 末尾弹出」；
   - 自动生成时间轴 —— **两行动画行**：行1 字素行（谜面字）；行2 同时承载部件落点 / 合成结果 / 谜底槽位；**配对的合成结果直接在它对应的谜底槽位上成形**（不再先弹在中间再横移过去，省掉整个"位移"阶段），谜底顺序由槽位本身表达；画布 640×210 贴边致密；支持播放/暂停/逐帧/拖动进度。
   - **谜底只有一个颜色**：落位的合成结果、没有来源时兜底弹出的谜底字、以及「谜底」行标签，统一用谜底色 `#0c8599`。早先落位用青、兜底 reveal 用紫，同一行会"先青后紫"，看上去像"谜底变了个颜色"而不是"答案来了" —— 那个额外的 1.0s 补色段一并消失（只有在谜底字确实没有任何来源时才保留兜底弹出）。
   - **长谜面自动换行 + 按行数自动降字号**（支持 14~20 字甚至更长）：先按基准字号算每行容量，若超出**行数上限**（谜面 3 行 / 行2 2 行）则**自动降字号**（每次 2px），直到回到上限内或触到**字号下限**（谜面 34px / 行2 40px）——即"宁可行数多一点，也不把字缩到看不清"；行内始终保持**平衡换行**（16 字 = 8+8，20 字 = 7+7+6，25 字降为 48px 后 9+9+7）并逐行居中；行2 的合成结果/谜底槽位超过容量时同样按阅读顺序换行成网格。
   - **画布高度自适应**：换行后只向下扩展高度（短谜面仍是 640×210，体积不变），实际尺寸挂在时间轴上，预览舞台、尺寸提示与三种导出格式全部自动跟随。
   - **行标签**（覆盖层，不占独立行）：行1 左端常显「谜面」（贴首行）；行2 左端在**第一个合成结果落到谜底槽位时淡入「谜底」**（没有落位合成结果时退化为揭示场景起点）。
5. **导出（格式可选，全部透明背景）**：
   - **GIF 动图**：1 位透明 + 全局 ≤256 色调色板（网页内原生编码，无需任何外部脚本/依赖）；
   - **APNG 动图**：真彩色 + 256 级 Alpha，半透明边缘最平滑（体积略大于 GIF）；
   - **SVG 静图**：导出当前画面为矢量图，可无损放大、便于二次编辑；
   - 可选 6/12/24 fps、1x/2x、循环/单次；预览与导出共用同一渲染路径，所见即所得。
   - **预览窗口与导出同比例**（短谜面 640×210，长谜面自动变高），画布标题旁实时显示当前导出尺寸（如 1x=640×210 / 2x=1280×420），预览无黑边、即导出所见。
   **为公众号嵌入优化**：画布 640×210 紧凑两行布局（比早期 1000×500 像素面积少约 73%）——宽度也从 1000 压到 640，接近公众号约 350px 的显示宽度，公众号内按宽度缩放时字被放大的幅度更小、更清晰；
   建议用 **12 fps + 1x** 导出即可保持清晰且文件最小（2x=1280×420 仅需要在放大查看时选用）。
   **GIF 的固有限制**（选 APNG 可避免）：透明只有 1 位（无半透明，文字边缘会有轻微锯齿）、颜色量化到 256 色（渐变处可能有轻微色带）；
   GIF 的优势是通用性最好（任何聊天工具/旧设备都能显示），APNG 的优势是透明与色彩更细腻。

想先看效果，点页头的「示例：十八口 → 杏」即可一键跑完十+八=木 → 木+口=杏 的完整流程；
画布空态和「使用说明」面板里是同一个入口。

## 运行

```bash
# 方式一：直接双击
open web/index.html

# 方式二：本地静态服务器（推荐，体验一致）
cd web && python3 -m http.server 8123
# 浏览器打开 http://127.0.0.1:8123
```

导出 APNG 需要在支持 `CompressionStream` 的现代浏览器中运行（Chrome 80+ / Firefox 113+ / Safari 16.4+）。

### 视觉与可访问性自查（可选，需要本机 Chromium 内核浏览器）

引导层与工作台改动后做过真实浏览器体检（Edge headless + CDP 量真实布局）：在
1560 / 1200 / 1000 / 760 / 380px 五个宽度下，**无横向溢出、无可点目标小于 24px、
正文最小对比度 5.12:1**（配对看板处 5.46:1）、身份徽标不越出容器也不压到相邻字块、
待合并托盘始终紧跟在字素池下方。配对看板的每行是 `左侧方块 → 连接线（带箭头）→ 谜底位`
首尾相接；≤560px 自动竖排（连接线转向下），阅读顺序不变。
宽屏时池子里每个来源字占一行（来源字标签与零件同行），380px 时自动降级成"标签一行、零件一行"。

**高度取舍（诚实说明）**：字素池为了"跨字混选"把零件全部摊开，代价是纵向变长 ——
两个字的谜面池子约 216px（和早期"一张字卡放当前字零件"基本持平），
**16 字的谜面则会到 ~1320px（需要滚动）**，换来的是不必再逐个点开字卡找零件。
零件做成横向小药丸（约 36px 高）就是为了把这个代价压下来。

`test_gif.mjs` 会写出 `web/test/sample.gif` 供肉眼查看；编码器另用 Python PIL 做过交叉校验
（40 万像素级往返、透明帧、码宽增长/字典重置路径均一致）。

## 设计与限制（对应整体规划）

- **svg 渲染 + 确定性时间轴**：所有画面是 `stateAt(t)` 的纯函数，预览与 APNG 逐帧导出完全一致；
  这是相对"CSS transition + 截图"方案更可靠的做法。
- **字形**：网页版用系统字体渲染 SVG `<text>`；打包桌面版时应内嵌字体（如思源黑体子集），
  避免 Windows/macOS 字体差异导致导出不一致。
- **位置语义**：拆字库只有"拆成哪些部件"、没有"左右/上下结构"位置信息，因此拆解采用"部件统一落到行2"的排布
  （部件组以字中心向两侧展开，组宽不超过字距；行2 = 部件落点 + 合成结果 + 谜底槽位，第二、三阶段合一）；
  短谜面画布 640×210、只有两行动画行，上下贴边无留白；**长谜面/多结果按每行容量自动平衡换行 + 按行数自动降字号**（`fitFont`：行数超上限则字号 −2px，下限 34/40px；`perLine = ⌊(W-2×64)/(字号+8)⌋`），画布高度由内容算出（`tl.H`），因此只在需要时才加高，且降字号后常比“不降字号多一行”更矮、更省体积；「谜面」「谜底」以左端行标签（覆盖层，`overlays` + `opacityAt`）贴在行内，不占独立行；
  若需要更地道的字形重构动画，后续可引入 Hanzi Writer 的笔画路径数据。
- **合成结果直接落位（无位移阶段）**：配对决定「这次合并填哪一个谜底槽位」，`sceneMerge`
  的合并点 `cx/cy` 直接取该槽位坐标，合成结果就在谜底位上弹出成形；落位单元显示的是
  **该槽位的谜底字**，所以即使手动把「杏」配到「花」的槽上，谜底顺序也不会被弄反。
  **中间产物同样一次到位**：反向遍历所有合并，凡是被后续合并当输入用的结果，落点**直接取
  消费者的落点**（`十八口` 里 `木` 一出现就在最终谜底位 320，而不是先弹在合并层 275 再横滑
  过去）。否则「拼出一个字」和「把它移到谜底位」是两段运动，一段合成要看两次位移。
  这样比"先合并到中间、再横移变形"少一整个阶段（`sceneDisplaceMorph` 仍保留在引擎里备用）：
  `十八口→杏` 由 5.4s 降到 2.9s、`木口艹化→杏花` 由 6.8s 降到 2.9s。
  没有任何合成结果落位的谜底字才走 `sceneReveal` 原位弹出（并压暗背景，压暗名单**不含**
  已落位的合成结果——它们现在就是谜底本身）；末尾固定 0.5s `sceneHold` 定格，
  让最后一帧看得清、循环播放不"闪回"。
- **透明背景的实现**：SVG 渲染层不画任何背景矩形（只有字形），导出时 `clearRect` 后逐帧
  `drawImage`，再由编码器按 RGBA 写出——APNG 为颜色类型 6（真彩色 + Alpha），GIF 用索引 0
  作透明色，因此三种导出格式都是真正的透明背景（网页预览区的棋盘格即表示该透明区域）。
- **APNG / GIF 编码器均为自研**（各约 150~260 行），避免了 `canvas2apng`、`gif.js` 等第三方库的依赖与维护风险；
  GIF 的 LZW 与码宽增长逻辑对齐 omggif（MIT）并用 PIL 交叉校验；GIF 格式固有限制（1 位透明、256 色）见上；
  SVG 是矢量静图（当前画面），可直接嵌网页或二次编辑。
- **身份只分两类（字素 / 衬字）**：算法实际只区分"参与拆合 / 不参与拆合"两种行为，界面就只给两类，
  不多不少。谜界会把不拆的字再细分为抱合字（离合动作）与指示字（方位取舍），但本工具对两者
  完全同构；且用「抱合字」当伞形词会被谜友认为概念扩大化（王守秾《抱合词的定义》），
  故取谜界已提出的中性伞形词「衬字」。配色仍保留教学价值：看动画的人能一眼看出哪些字参与拆合；
  但界面自身的完成态（✓ / 已完成 / 恰好匹配）一律用墨色，不借用字素绿，免得绿勾被误读成"字素"。
- **谜材库**（caizi-data/）暂未接入本页，后续可作为"选谜底"的辅助面板复用。
