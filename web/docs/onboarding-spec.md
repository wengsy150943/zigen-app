# 字谜离合动画工坊 · 上手体验优化规格（v0.2 → v0.3）

> 面向对象：本页前端（`web/index.html`、`web/app.js`），以及 v0.3 追加的
> 时间轴流程精简（`web/studio.js` / `web/engine.js`）。拆字算法与三种导出编码器**不在范围内**。

## 1. 问题陈述

工坊的核心流程是「输入谜面 → 标角色 → 拆解合并 → 出谜底动画」四步，但界面把四步平铺成
四张同时展开、同时可交互的卡片：**没有任何步骤状态、前置门控或"下一步"指引**。

结果是第一次打开的人面对三个问题都得不到回答：

1. **从哪开始？** 唯一的示例入口是页头右上角两个灰色按钮，很容易被忽略；
   右侧画布在未生成动画时是一片空棋盘格，没有任何提示。
2. **做到哪了？** 没有进度显示，步骤卡片没有完成标记，`#status` 提示条位于第四张卡片底部，
   在长卡片滚动时基本看不到。
3. **下一步做什么？** 术语（抱合字 / 指示字 / 字素）只用一段 12px 灰色小字集中解释，
   需要先读完才能动手；错误提示只说"不合法"，不说怎么办。

**不解决的代价**：新用户需要通读 README（109 行）才能完成第一条动画；
谜友/公众号作者这类非技术用户大概率在第二步放弃。

## 2. 目标

| # | 目标 | 衡量方式 |
|---|------|----------|
| G1 | 打开页面 30 秒内能产出第一条完整动画 | 从冷启动到"导出"按钮可用的操作步数 ≤ 3（点示例 → 播放 → 导出） |
| G2 | 任意时刻界面都能回答"我在哪 / 下一步做什么" | 4 个步骤常驻状态（未开始 / 进行中 / 已完成 / 待解锁），每步有明确的下一步按钮 |
| G3 | 术语零阅读成本 | 角色含义内联在按钮上，不必读段落；关键提示带"下一步"动作 |
| G4 | 空状态不再是空白 | 画布空态、步骤空态都给出可点的下一步 |
| G5 | 零回归 | 全部既有 Node 测试通过；导出产物与优化前逐字节一致 |
| G6 | 动画不留死时间 | 每个场景都必须产生可见变化；总时长只由"拆解 / 合并 / 0.5s 定格"构成 |
| G7 | 操作对象即谜面本身 | 点某个字就能改它的身份、下面的池子里直接挑它的零件，不必先去别处「标注」或「找块」 |
| G10 | 零件池是共享的，不被来源字切碎 | 池子里所有零件属于同一个选择集：点 A 字的零件和 B 字的零件能直接拼成一个新字，中途不需要切换任何面板 |
| G12 | 谜底是一次亮相，不是一次换装 | 谜底位的字从头到尾一个颜色；同一个字不会既以合成结果的身份出现、又在末尾被弹出一个 |
| G11 | 身份标记两类一致 | 一个字的身份必须在字块上可读：字素与衬字都挂徽标、都用各自的颜色，不能只有非默认的那一类有标记 |
| G9 | 一个动作一次位移 | 任何单元从出现到被消耗，位置不再变化；每个合成结果只成形一次 |
| G8 | 分类只反映算法真实差异 | 身份类别数 == 算法实际区分的行为数（2），不多不少 |

## 3. 非目标（Non-Goals）

- **不做拖拽**：保持"选定式"交互，拖拽是另一条独立的技术路线。
- **不改动画与导出**：`engine.js` / `svg.js` / `apng.js` / `gif.js` / `studio.js` 逻辑一行不动，
  导出的 GIF/APNG/SVG 必须与优化前一致。
- **不引入框架、构建或 CDN**：`web/index.html` 双击即用这一约束保持。
- **不做强制引导遮罩 / 分步 tour**：符合"用户应能跳过教程"的无障碍要求，
  帮助用可关闭的面板（`? 使用说明`）而不是阻塞式 overlay。
- **不接入谜材库**（`caizi-data/`）：与上手体验无关。
- **不做移动端优先重排**：目标场景是桌面浏览器 + 公众号导出；
  1020px 以下退化为单列，保证不破版即可（380px 实测仍无横向溢出）。
- **不废弃 `sceneDisplaceMorph`**：引擎 API 保留并有测试覆盖，只是当前时间轴不再使用它 ——
  将来若要做"先演示合成、再归位到谜底"的讲法，不必重写引擎。
- **不恢复「指示字」第 3 类**：它与「衬字」在本工具里同构，加回来只是多一个没有操作差异的
  选项（见 §6b）。
- **不把「增损字」单列**：谜界的用字表把"增"与"减"分开，但本工具不支持"减损"
  （拆字库没有位置信息，"牛去掉尾巴"做不到），多一类也没有对应操作。

## 4. 用户故事

**谜友（首次使用者）**
- 作为第一次打开工坊的谜友，我想看到"试一个"的现成例子并一键跑通，
  这样我不用先弄懂术语就能看到这工具能做什么。
- 作为谜友，我想知道现在该操作哪一步，这样我不用回头翻说明。
- 作为谜友，我想在按钮上直接看到每个身份是什么意思，这样我不用猜术语就能标注。
- 作为谜友，我不确定每个字该标什么时，想有一个"全都按字素处理"的快捷方式，
  因为绝大多数谜面就是纯拆字。

**公众号作者（重复使用者）**
- 作为内容作者，我想明确知道导出格式该选哪个，这样我不用试三种格式比体积。
- 作为内容作者，我想在标注或合并出错时立刻知道怎么改，而不是只看到"不合法"。

**边界与错误状态**
- 谜面为空 / 只有标点 → 明确提示"只填谜面那一句"。
- 一个字的角色没标完就往下走 → 提示还差几个字。
- 没有字素就开始拆解 → 提示先回上一步标字素，并给出跳转。
- 谜底未填就导出 → 提示先填谜底，并聚焦到输入框。

### P0-v0.3g（第八轮：身份笔 + 拖框划选）

| ID | 需求 | 验收标准 |
|----|------|----------|

## 6b. 分类结论（v0.3 定案：两类）

**结论：只保留两类 —— `字素`（参与拆合）与 `衬字`（不参与拆合）。**

推理链：

1. 算法只有两种行为：参与拆合 / 不参与拆合。原「抱合字」与「指示字」在代码里完全同构
   （都只是"不参与拆合 + 谜面行着色"），分出来没有对应操作 —— 这是"功能上是 2 类"的由来。
2. 那要不要把它们并进「抱合字」？**不要。** 谜界对此本就有争论：王守秾《抱合词的定义》
   明确反对把指示字并进抱合字（见[原文](http://www.zhgc.com/BBS/printpage.asp?BoardID=95&id=463632)，
   "为了不使『抱合字』的概念扩大化……我们不妨把它取名为〔衬词〕"）。用「抱合字」当伞形词
   会被谜友认为概念错用。
3. 所以取谜界已经提出的中性伞形词 **「衬字」**，涵盖离合动作（合、出、去）与
   方位取舍（头、尾、边），描述里把两类例子都写出来。
4. 「字素」不是谜界通用词（多用"主体字/本体字"），但对非谜友更直白，靠内联释义兜住。
5. 配色仍保留教学价值：**看动画的人**能一眼看出哪些字参与拆合。但界面自身的完成态
   （✓ / 已完成 / 恰好匹配）不再借用字素绿，改回墨色 —— 否则绿勾会被误读成"这个字是字素"。
